ZEUS CLOUD DEPLOYER v3.3 – UPDATE GUIDE

1) Replace the GitHub project files
- Extract the v3.3 package.
- Upload/replace the contents of the cloudflare-deployer folder into the same existing repository path.
- Preserve the existing production Root Directory setting. For the previously used repository layout, it remains: cloudflare-deployer
- Preserve Build command: exit 0
- Preserve Build output directory: public

2) No new D1 Binding is required
- Keep the existing dashboard D1 binding with variable name DB.
- Keep VAULT_ENCRYPTION_KEY unchanged. It is required to decrypt the Cloudflare API Tokens already stored in the accounts table.
- The new table account_deploy_settings is created automatically the first time an account is selected in the updated panel.
- migrations/0002_account_deploy_settings.sql is optional and should only be executed manually if you prefer to create the table in advance.

3) Per-account settings
- Select a saved Cloudflare account.
- The first selection creates random names for Worker, D1, and KV (zeus-*, zeus-db-*, zeus-kv-*).
- Values are stored in the dashboard D1 database, separately for each account.
- Use the Random buttons to replace any name; the new value is saved automatically.
- Switching to another account loads that account's own saved names and settings.

4) Panel URL
- The returned panel link always ends with /panel.
- If the deployed source requires a secret route prefix, enter the prefix in Panel path, e.g. qna61nmQZUnG/panel.
- If you enter only qna61nmQZUnG, the app appends /panel automatically.
- If you enter only panel, the result is https://WORKER.ACCOUNT.workers.dev/panel.

5) Automatic health checking and rebuild
- Health check is ON by default.
- Automatic rebuild is ON by default.
- After a successful Deploy, monitoring starts automatically.
- When a previously deployed account is selected later, monitoring resumes automatically if enabled for that account.
- Automatic Clean Rebuild starts on the first real unhealthy result. The one-hour anti-loop cooldown remains between attempts and is cleared by a healthy health check.
- Browser-based monitoring requires the panel tab to stay open. It does not continue after the tab/browser closes. Always-on monitoring requires a separate scheduled Cron Worker.
- Automatic rebuild requires the signed-in user to have Clean Rebuild permission for that Cloudflare account.

6) Safe update notes
- Do not delete the dashboard D1 database.
- Do not change VAULT_ENCRYPTION_KEY.
- This update adds an account-specific settings table; it does not change the existing users, sessions, accounts, or permissions tables.


نسخه One-Failure: بازسازی خودکار پس از اولین خطای واقعی Health Check انجام می‌شود و Worker قبلی حذف و دوباره نصب می‌شود. محدودیت ایمنی یک‌ساعته بین تلاش‌ها حفظ شده و پس از مشاهده پاسخ سالم برای خرابی جدید از نو محاسبه می‌شود. برای اعمال تغییر، Pages را با Push به GitHub به‌روزرسانی و Cron Worker را با دستور `npx wrangler deploy --config cron-worker/wrangler.toml` مجدداً deploy کنید. D1 و Secret قبلی را حفظ کنید.


One-Failure update: The automatic Clean Rebuild threshold is fixed at one real unhealthy Health Check result; legacy D1 values of 3 are ignored and the old cooldown timestamp is reset once during upgrade. It deletes the existing Worker and installs the saved source again. A one-hour anti-loop cooldown remains between rebuild attempts and resets after a healthy check. API/auth/permission/token-decryption errors remain inconclusive. Redeploy Pages through GitHub and redeploy the scheduled Worker with `npx wrangler deploy --config cron-worker/wrangler.toml`; keep the existing D1 and Secret unchanged.

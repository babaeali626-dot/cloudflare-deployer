مدیریت حساب‌های Cloudflare

ساخت فرم API Token با دسترسی‌های لازم

صفحه رسمی Cloudflare باز می‌شود و نام و مجوزهای Worker Scripts، D1، KV و Route را از قبل انتخاب می‌کند. تأیید نهایی و کپی Token با خود شماست.

نکته مجوز: در مدل جدید Cloudflare، ساخت یا حذف Worker جدید ممکن است به نقش Workers در سطح Product با دسترسی Admin نیاز داشته باشد؛ مجوز Workers Scripts Edit برای به‌روزرسانی Worker موجود است. اگر هنگام ساخت Worker یا Clean Rebuild خطای 403 گرفتید، نقش Admin را در Cloudflare بررسی کنید.

ساخت خودکار توکن ↗

Token کامل به هیچ API فهرست حساب‌ها یا کاربران بازگردانده نمی‌شود؛ فقط در زمان ثبت، رمزگذاری شده و سمت سرور نگهداری می‌شود.

فقط حساب‌هایی نمایش داده می‌شوند که مدیر به این نام کاربری اجازه دسترسی داده است.

همه تنظیمات در یک صفحه

نام Worker برای همین حساب ذخیره می‌شود و در ورود بعدی نیز باقی می‌ماند.

اگر Worker یک مسیر محرمانه قبل از panel دارد، آن را هم وارد کنید؛ نمونه: qna61nmQZUnG/panel. اگر وارد نکنید، لینک به /panel ختم می‌شود.

ساخت دیتابیس D1 (اتصال خودکار)
در صورت نیاز، دیتابیس ساخته می‌شود، جدول‌های پایه به‌صورت خودکار Migration می‌شوند و Binding پیش‌فرض DB به Worker تزریق می‌شود.
ساخت و اتصال KV (اختیاری)
ساخت Namespace و اتصال آن به Worker.
مبهم‌سازی سورس کد (Obfuscator)
تبدیل رشته‌ها با XOR/Base64؛ این روش رمزنگاری امن نیست و ممکن است با بعضی سورس‌ها ناسازگار شود.
حذف و بازسازی مجدد Worker (Clean Rebuild)
Worker با همین نام حذف و از سورس انتخابی دوباره نصب می‌شود.
هشدار: Clean Rebuild قبل از نصب، Worker قبلی را حذف می‌کند. اطلاعاتی که فقط در تنظیمات/Secretهای Worker ذخیره شده‌اند ممکن است از بین بروند. برای Workerهای دارای Durable Object بدون پشتیبان استفاده نکنید.
